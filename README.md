# KTV 練唱

自己在家練唱用的本機工具：從 YouTube Music／YouTube 點歌，AI 去掉人聲，配上同步歌詞，用 KTV 式雙行歌詞跟著唱。

- **KTV 雙行歌詞**：上行是正在唱的、下行是下一句，兩行輪流替換，唱過的字從左到右變色
- **兩種點歌來源**：預設 YouTube Music（唱片公司上架的錄音室音軌，長度和專輯一致）；找不到的再切到 YouTube（翻唱、冷門歌）
- **歌詞自動核對時間**：用分離出來的人聲軌比對歌詞每一句的開頭，挑時間最準的一份；MV 多一段前奏也會自動算出要延後幾秒
- **導唱音量**：人聲從 0%（純伴奏）到 100%（原唱）隨時調
- **繁體中文**：簡體歌詞自動轉成繁體（台灣字形），歌名、歌手也一樣
- **日文羅馬拼音**：原文／原文＋上方小字拼音／只有拼音，三段切換
- **間奏倒數**：前奏、間奏太長時，下一句上方出現「0 0 0 0 |」逐拍倒數
- **全部歌詞**：右側打開整首歌詞，正在唱的那句標亮、自動捲到眼前；點任何一句就跳到那裡接著唱
- **歌詞時間微調**：每首歌各自記住；歌詞配錯可以換一份或自己貼 LRC
- **快取**：處理過的歌留在本機，第二次點直接開唱

> 僅供個人自用。用 yt-dlp 下載 YouTube 音訊違反 YouTube 服務條款，請不要做成公開服務。

## 需求

- Windows（其他系統也行，只是啟動腳本是 PowerShell）
- [uv](https://docs.astral.sh/uv/)（會自動安裝 Python 3.12）
- Node.js 20 以上（前端建置用，也是 yt-dlp 解析 YouTube 需要的 JS 執行環境）
- [ffmpeg](https://ffmpeg.org/)（要在 PATH 裡）
- NVIDIA 顯卡（選用）：有 CUDA 時一首歌分離約 10–20 秒；只有 CPU 也能跑，但會慢很多

## 啟動

第一次先安裝後端套件（PyTorch CUDA 版約 2.5GB）：

```bash
cd backend
uv sync
```

之後每次雙擊 `start.bat`，或在 PowerShell 執行：

```powershell
.\start.ps1
```

第一次會自動建置前端，然後啟動後端並開啟 <http://127.0.0.1:8000>。改過前端程式碼後用 `.\start.ps1 -Rebuild` 重新建置。

### 開發模式

```bash
cd backend && uv run uvicorn app.main:app --reload --port 8000
```

```bash
cd frontend && npm install && npm run dev
```

前端開發伺服器在 <http://localhost:5173>，`/api` 會轉給後端。後端不在 8000 時，用環境變數 `KTV_API` 指定（例如 `KTV_API=http://127.0.0.1:8001`）。

## 運作方式

```
搜尋 ──▶ YouTube Music：ytmusicapi 搜「歌曲」，現場版、伴奏版標出來排到後面
     ──▶ YouTube：yt-dlp 搜尋（同時搜「歌名＋official audio」；和多數結果同長度的排前面）
點歌 ──▶ yt-dlp 下載音訊 ──▶ Demucs htdemucs 拆成人聲／伴奏兩軌（mp3 320k）
     ──▶ LRCLIB 收集候選歌詞（精確比對、歌名、MV 標題【】「」裡的歌名）
     ──▶ 每份候選都和人聲軌核對時間，挑最吻合的；需要位移就自動設好 offset
     ──▶ 簡體歌詞用 OpenCC 轉繁體；日文歌用 cutlet 產生羅馬拼音
播放 ──▶ 瀏覽器用 Web Audio 同時播兩軌（取樣級同步），導唱滑桿只調人聲軌音量
```

資料存在 `data/songs/<影片 ID>/`：`vocals.mp3`、`inst.mp3`、`meta.json`（歌詞、拼音、時間偏移、核對結果）。刪掉資料夾就會重新處理。

### 歌詞對時

LRCLIB 上同一首歌常有十幾份歌詞，長度欄位常標錯，時間軸也有準有不準，所以不靠長度挑，而是直接拿人聲軌比對（`backend/app/sync.py`）：

1. **粗對**：人聲軌每 50ms 標記「有沒有在唱」。歌詞整體往前後挪（±90 秒），找「句子裡有聲、句子外沒聲」最明顯的位置。
2. **細對**：每一句開頭，人聲應該剛好冒出來。以 10ms 為單位找所有句首都對上人聲起音的位置，用 z 分數判斷確不確定。

判定門檻用 5 首歌、70 組正確／錯誤歌詞（加上人工接前奏、剪前奏）校正：正確的全部判為吻合，錯誤的（別首歌）全部判為對不上。實測周杰倫〈晴天〉官方 MV（比錄音室版長 48 秒）會自動算出歌詞要延後 14.7 秒，換成任何一份〈晴天〉歌詞都落在 14.65–14.76 秒。

結果顯示在三個地方：換歌詞對話框裡每一份歌詞的標籤（時間吻合／吻合，延後 X 秒／時間對不上）、練唱控制列「歌詞時間」旁的標籤，以及對不上時畫面上的提示。

### 繁體中文

簡體歌詞轉繁體用 OpenCC 的 `s2tw`（`backend/app/zh.py`）：只換字、不換詞（「视频」變「視頻」而不是「影片」），每句字數不變，變色進度才對得上唱的音節。有假名的日文、本來就是繁體的歌詞不會動；舊的歌第一次打開時自動轉。

### 音質

| | 來源（YouTube 免費帳號能拿到的最好格式） | 分離後輸出 |
|---|---|---|
| 格式 | Opus 約 130 kbps、48 kHz | MP3 320 kbps、44.1 kHz（Demucs 用 44.1 kHz） |
| 高頻上限 | 約 20.2 kHz | 約 20.1 kHz |
| 爆音 | 解碼後峰值 +1 dBFS | 兩軌一起降約 2 dB，峰值 −1 dBFS 以下，不會爆音 |

伴奏是鼓、貝斯、其他三軌相加；人聲軌是「原曲 − 伴奏」，所以導唱開到 100% 時兩軌相加就是原曲（實測和原曲的波形誤差 −39 dB，主要是 mp3 編碼）。YouTube Music 和 YouTube 是同一套音訊串流，兩邊音質一樣；差別在 Music 的歌曲是錄音室版本，長度和歌詞對得上。

### 為什麼只有 YouTube Music／YouTube

其他免費來源都試過或查過：SoundCloud 上主流華語、日文歌幾乎只有翻唱、混音和 96 kbps 的二創；Spotify、Apple Music、KKBOX 有 DRM 無法取用；Bandcamp 只有獨立音樂。

## 已知限制

- LRCLIB 大多只有逐行時間，變色是依整行長度平均推進，不會完全貼合實際唱法。
- 自動對時只能補「整首一起位移」。現場版節奏不同，或 MV 剪掉、插入一段，只會部分對得上，會標成「時間對不上」，請換錄音室版本或手動微調。
- 人聲很密的歌（例如饒舌）判定比較保守，偶爾明明對得上卻標成對不上；這時直接播放確認，或用 `[` `]` 微調。
- 還沒有：升降 Key、邊分離邊播、中文注音、韓文羅馬拼音。
